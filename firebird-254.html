    14.1.2. Generación de las bases de datos

    Al igual que hicimos con Oracle, DB2 y SQL Server, tendremos que instalar el controlador JDBC de Firebird en el repositorio local de Maven.

      

    El archivo [install.bat] contiene el siguiente código:

    "%M2_HOME%\bin\mvn.bat" install:install-file -Dfile=jaybird-2.2.7.jar -Dpackaging=jar -DgroupId=org.firebirdsql.jdbc -DartifactId=jaybird -Dversion=2.2.7

    donde [%M2-HOME%] es el directorio de instalación de Maven (véase la sección 23.2). Tras esta instalación, se puede hacer referencia al controlador JDBC de Firebird en los archivos [pom.xml] utilizando la siguiente dependencia:

    
        <dependency>
            <groupId>org.firebirdsql.jdbc</groupId>
            <artifactId>jaybird</artifactId>
            <version>2.2.7</version>
</dependency>

    A partir de aquí, las conexiones a las bases de datos Firebird se realizan utilizando las credenciales [sysdba / masterkey]. Inicie Firebird y su cliente [IBManager] (véase la sección 23.10). Las bases de datos Firebird son únicas, ya que están encapsuladas en un único archivo.

    • En [1], el archivo se encuentra en [<ejemplos>\spring-database-config\firebird\databases\DBPRODUITS.GDB];
    • Al igual que con Oracle, las claves primarias se generan mediante secuencias.

    Procedemos de la misma manera para cargar la base de datos [dbproduitscategories], que se encuentra en [<examples>\spring-database-config\firebird\databases\DBPRODUITSCATEGORIES.GDB]

      

    Ahora, ejecuta las configuraciones:

    14.2. Configuración de la capa JDBC

     

    El proyecto [firebird-config-jdbc] configura la capa [JDBC] de la siguiente arquitectura de prueba:

    El proyecto es análogo al proyecto de configuración [oracle-config-jdbc] para la capa JDBC del SGBD MySQL (véase la sección 10.2). A continuación se presentan únicamente los cambios:

    El archivo [pom.xml] importa el controlador JDBC de Firebird:

        <artifactId>spring-boot-starter-parent</artifactId>
        <version>1.2.3.RELEASE</version>
    </parent>
 
    <dependencies>
        <!-- dépendances variables ********************************************** -->
        <!-- driver JDBC from SGBD -->

        ...
    </dependencies>

</project>
    • líneas 18–22: el controlador JDBC de Firebird;
    • líneas 24–33: las dependencias necesarias para el controlador JDBC de Firebird;

    El segundo cambio se encuentra en la clase [ConfigJdbc], que define las credenciales de la base de datos:

    
    // paramètres de connexion
    public final static String DRIVER_CLASSNAME = "org.firebirdsql.jdbc.FBDriver";
    public final static String URL_DBPRODUITS = "jdbc:firebirdsql:localhost/3050:<exemples>/SPRING-DATABASE-CONFIG/FIREBIRD/DATABASES/DBPRODUITS.GDB";
    public final static String USER_DBPRODUITS = "sysdba";
    public final static String PASSWD_DBPRODUITS = "masterkey";
    public final static String URL_DBPRODUITSCATEGORIES = "jdbc:firebirdsql:localhost/3050:<exemples>/SPRING-DATABASE-CONFIG/FIREBIRD/DATABASES/DBPRODUITSCATEGORIES.GDB";
    public final static String USER_DBPRODUITSCATEGORIES = "sysdba";
public final static String PASSWD_DBPRODUITSCATEGORIES = "masterkey";
    • Líneas 3 y 6: Debe introducir las rutas exactas de ambas bases de datos;

    La tercera modificación que se puede realizar es la del número máximo de parámetros que puede admitir un [PreparedStatement]:

    
    // max number of parameters of a [PreparedStatement]
    public final static int MAX_PREPAREDSTATEMENT_PARAMETERS = 1000;

    La prueba [JUnitTestPushTheLimits] genera sentencias SQL para 5000 productos, lo que generará objetos [PreparedStatement] con 5000 parámetros. MySQL admitía este valor. Firebird no.

    El cuarto cambio se refiere a una palabra reservada en Firebird-config-jdbc: PASSWORD. Por lo tanto, la columna [USERS.PASSWORD] ha pasado a llamarse [USERS.PASSWD]:

    
public final static String TAB_USERS_PASSWORD = "PASSWD";
public static final String SELECT_USER_BYLOGIN = "SELECT u.ID as u_ID, u.VERSIONING as u_VERSIONING, u.NAME as u_NAME,u.LOGIN as u_LOGIN,u.PASSWD as u_PASSWORD FROM USERS u WHERE u.LOGIN= :login";

    14.3. Configuración de la capa JPA de OpenJPA

     

    El proyecto [firebird-config-jpa-openjpa] configura la capa [JPA] de la arquitectura de prueba:

    Este proyecto es similar al proyecto de configuración [firebird-config-jpa-openjpa] para la capa JPA de OpenJPA del SGBD Oracle (véase la sección 10.5). De hecho, ambos SGBD utilizan secuencias para generar claves primarias. Solo hay que realizar un cambio. Se encuentra en la definición del bean [jpaVendorAdapter] en la clase [ConfigJpa]:

    
    // the provider JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        OpenJpaVendorAdapter openJpaVendorAdapter = new OpenJpaVendorAdapter();
        openJpaVendorAdapter.setShowSql(false);
        openJpaVendorAdapter.setDatabase(Database.DEFAULT);
        openJpaVendorAdapter.setGenerateDdl(true);
        return openJpaVendorAdapter;
}
    • Línea 6: Le indicamos a la implementación de JPA que va a trabajar con un DBMS no reconocido. La implementación de JPA adoptará entonces los tipos de datos SQL estándar.

    Una vez realizados estos cambios, la ejecución de la configuración [spring-jpa-generic-JUnitTestDao-openjpa] debería completarse con éxito.
