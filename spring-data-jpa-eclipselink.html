    • líneas 10–14: el proyecto Maven principal que especifica las versiones de la mayoría de las dependencias que requiere el proyecto;
    • líneas 19–22: la biblioteca EclipseLink;
    • líneas 26-29: la biblioteca Spring Data;
    • líneas 32-34: el proyecto de configuración de la capa JPA se basa en el proyecto de configuración de la capa JDBC, que define, entre otras cosas, el controlador JDBC para el SGBD que se está utilizando y los detalles de conexión a la base de datos;
    • líneas 35–40: el proyecto de configuración de la capa JDBC incluye la biblioteca [Spring JDBC], que aquí se sustituye por la biblioteca [Spring Data JPA]. Por lo tanto, especificamos que no se incluya en las dependencias del proyecto. Sin embargo, si permanece, esto no provoca ningún error;
    • El complemento de las líneas 58-81 implementa el entrelazado de entidades JPA. Lo que se conoce como entrelazado es la transformación (enriquecimiento) de las entidades JPA para que admitan la carga diferida. No fue necesario configurar Hibernate para que se produjera este entrelazado. Para EclipseLink, se requiere un complemento de Maven. Pasé mucho tiempo intentando averiguar cómo forzar a EclipseLink a respetar el atributo [fetch = FetchType.LAZY] de la anotación [@ManyToOne] que aparece a continuación: 
    
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = ConfigJdbc.TAB_PRODUITS_CATEGORIE_ID)
private Categorie categorie;

    La especificación JPA establece que el atributo [fetch = FetchType.LAZY] de la anotación [@ManyToOne] es una «sugerencia» que la implementación de JPA no está obligada a seguir. Y, de hecho, EclipseLink no lo sigue por defecto. Se requiere una configuración especial para que lo haga. Tras muchas búsquedas infructuosas, encontré la solución en la URL citada en la línea 51. Cuando se incluyen las líneas 58-81 en el archivo [pom.xml], Eclipse informa de un error en el archivo. Se trata de un problema de configuración con el complemento [m2e], que gestiona los proyectos Maven dentro de Eclipse. Es necesario añadir las líneas 83-119 para resolver el error.

    7.3.2. Configuración de Spring

     

    La clase [ConfigJpa] configura el proyecto Spring:

    
package generic.jpa.config;
 
import generic.jdbc.config.ConfigJdbc;
 
import javax.persistence.EntityManagerFactory;
 
import org.apache.tomcat.jdbc.pool.DataSource;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Import;
import org.springframework.orm.jpa.JpaTransactionManager;
import org.springframework.orm.jpa.JpaVendorAdapter;
import org.springframework.orm.jpa.LocalContainerEntityManagerFactoryBean;
import org.springframework.orm.jpa.vendor.Database;
import org.springframework.orm.jpa.vendor.EclipseLinkJpaVendorAdapter;
import org.springframework.transaction.PlatformTransactionManager;
 
@Configuration
@Import({ ConfigJdbc.class })
public class ConfigJpa {
 
    // the provider JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        // Note: JPA entities and Eclipselink configuration are in the META-INF/persistence.xml file
        EclipseLinkJpaVendorAdapter eclipseLinkJpaVendorAdapter = new EclipseLinkJpaVendorAdapter();
        eclipseLinkJpaVendorAdapter.setShowSql(false);
        eclipseLinkJpaVendorAdapter.setDatabase(Database.MYSQL);
        eclipseLinkJpaVendorAdapter.setGenerateDdl(true);
        return eclipseLinkJpaVendorAdapter;
    }
 
    // data source
    @Bean
    public DataSource dataSource() {
        // data source TomcatJdbc
        DataSource dataSource = new DataSource();
        // configuration access JDBC
        dataSource.setDriverClassName(ConfigJdbc.DRIVER_CLASSNAME);
        dataSource.setUsername(ConfigJdbc.USER_DBPRODUITSCATEGORIES);
        dataSource.setPassword(ConfigJdbc.PASSWD_DBPRODUITSCATEGORIES);
        dataSource.setUrl(ConfigJdbc.URL_DBPRODUITSCATEGORIES);
        // initially open connections
        dataSource.setInitialSize(5);
        // result
        return dataSource;
    }
 
    // EntityManagerFactory
    @Bean
    public EntityManagerFactory entityManagerFactory(JpaVendorAdapter jpaVendorAdapter, DataSource dataSource) {
        LocalContainerEntityManagerFactoryBean factory = new LocalContainerEntityManagerFactoryBean();
        factory.setJpaVendorAdapter(jpaVendorAdapter);
        factory.setDataSource(dataSource);
        factory.afterPropertiesSet();
        EntityManagerFactory entityManagerFactory = factory.getObject();
        return entityManagerFactory;
    }
 
    // Transaction manager
    @Bean
    public PlatformTransactionManager transactionManager(EntityManagerFactory entityManagerFactory) {
        JpaTransactionManager txManager = new JpaTransactionManager();
        txManager.setEntityManagerFactory(entityManagerFactory);
        return txManager;
    }
 
}

    Esta configuración es similar a la descrita en la sección 6.3.2 para la implementación de Hibernate JPA. Solo detallaremos las diferencias:

    • líneas 23-31: el bean [jpaVendorAdapter] ahora se implementa con EclipseLink;
    • líneas 50-58: en la versión de Hibernate JPA, el código era: 
    factory.setPackagesToScan(ENTITIES_PACKAGES);

    que se utilizaba para especificar dónde buscar las entidades JPA. Aquí, nos basamos en el archivo [persistence.xml] (comentario en la línea 25) (véase la sección 6.3.4) para:

    • definir las entidades JPA;
    • configurar EclipseLink para integrar estas entidades;

    7.4. El archivo [persistence.xml]

      
    
<?xml version="1.0" encoding="UTF-8"?>
<persistence version="1.0" xmlns="http://java.sun.com/xml/ns/persistence" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://java.sun.com/xml/ns/persistence http://java.sun.com/xml/ns/persistence/persistence_1_0.xsd">
    <persistence-unit name="generic-jpa-entities-dbproduitscategories" transaction-type="RESOURCE_LOCAL">
        <!-- entities JPA -->
        <class>generic.jpa.entities.dbproduitscategories.Categorie</class>
        <class>generic.jpa.entities.dbproduitscategories.Produit</class>
        <class>generic.jpa.entities.dbproduitscategories.User</class>
        <class>generic.jpa.entities.dbproduitscategories.Role</class>
        <class>generic.jpa.entities.dbproduitscategories.UserRole</class>
        <exclude-unlisted-classes>true</exclude-unlisted-classes>
        <!-- properties required for [@ManyToOne] to be searched in LAZY mode -->
        <properties>
            <property name="eclipselink.weaving" value="static" />
            <property name="eclipselink.weaving.lazy" value="true" />
            <property name="eclipselink.weaving.internal" value="true" />
        </properties>
    </persistence-unit>
</persistence>
    • línea 4: la unidad de persistencia. Puede tener cualquier nombre (atributo name);
    • líneas 6–10: las cinco entidades JPA que se van a gestionar;
    • La línea 11 es importante. A veces, un proyecto define entidades que se utilizan en diferentes contextos. La línea 11 garantiza que no habrá más entidades que las definidas en las líneas 5–10. Esto es importante cuando estas entidades se utilizan para generar las tablas de la fuente de datos. Tener entidades adicionales generaría tablas adicionales;
    • Líneas 13–17: configuración de EclipseLink para el entrelazado estático. Hay dos tipos de entrelazado:
      • [estático]: las entidades JPA se entrelazan tan pronto como se instancia la capa JPA;
      • [dinámico]: las entidades JPA se enriquecen (entretejen) la primera vez que entran en la capa JPA;

    7.5. Entidades JPA

      

    Las entidades JPA son las descritas en la sección 6.3.3 para la implementación de Hibernate, con dos diferencias:

    • todas las entidades JPA tienen la anotación [@Cache(alwaysRefresh = true)], que desactiva la caché de EclipseLink. En este documento, no se utilizan las cachés de las implementaciones JPA empleadas. La caché de EclipseLink parece estar habilitada por defecto y provocó errores en las pruebas. 
    
@Entity
@Table(name = ConfigJdbc.TAB_CATEGORIES)
@JsonFilter("jsonFilterCategorie")
@Cache(alwaysRefresh = true)
public class Categorie implements AbstractCoreEntity {
    • Todas las anotaciones [@OneToMany] van acompañadas de la anotación [@CascadeOnDelete]: 
    
    @OneToMany(fetch = FetchType.LAZY, mappedBy = "categorie", cascade = { CascadeType.ALL })
    @CascadeOnDelete
    private List<Produit> produits;

    Esta anotación interviene al generar tablas a partir de entidades JPA. Añade el atributo SQL [ON DELETE CASCADE] a las claves externas (en este caso, PRODUCTS[CATEGORY_ID] ---> CATEGORIES[ID]), lo que garantiza que, cada vez que se elimine una categoría de la tabla [CATEGORIES], también se eliminen los productos correspondientes de la tabla [PRODUCTS];

    Nota: Es importante señalar que esta anotación se utiliza tanto al crear la tabla, como acabamos de ver, como al realizar consultas en ella. EclipseLink asume que el atributo SQL [ON DELETE CASCADE] está presente y lo utiliza siempre que se le solicita eliminar una categoría. Su ausencia provocaría errores.
