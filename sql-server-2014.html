    13.1.2. Generación de las bases de datos

    Al igual que hicimos con Oracle y DB2, tendremos que instalar el controlador JDBC de SQL Server en el repositorio local de Maven.

      

    El archivo [install.bat] contiene el siguiente código:

    "%M2_HOME%\bin\mvn.bat" install:install-file -Dfile=sqljdbc4-3.0.jar -Dpackaging=jar -DgroupId=com.microsoft.sqlserver -DartifactId=sqljdbc4 -Dversion=4.0

    donde [%M2-HOME%] es el directorio de instalación de Maven (véase la sección 23.2, página 466). Tras esta instalación, se puede hacer referencia al controlador JDBC de SQL Server en los archivos [pom.xml] utilizando la siguiente dependencia:

    
        <dependency>
            <groupId>com.microsoft.sqlserver</groupId>
            <artifactId>sqljdbc4</artifactId>
            <version>4.0</version>
</dependency>

    A lo largo del resto de esta guía, las conexiones a las bases de datos de SQL Server se realizan utilizando las credenciales [sa / msde]. Inicie SQL Server y su cliente [MsManager] (véase la sección 23.9).

    • En [1], cargue el script SQL [<ejemplos>\spring-database-config\sqlserver\databases\dbproduits.sql];
    • En [2], no fue posible utilizar la misma tabla [PRODUCTS] para los proyectos [spring-jdbc-01 a 03]. El motivo es que:
      • los proyectos [spring-jdbc-01 y 02] insertan filas con sus claves primarias;
      • el proyecto [spring-jdbc-03] inserta filas sin claves primarias y espera que el SGBD las genere. Para que esto funcione, la clave primaria [ID] debe ser de tipo [Identity]. Sin embargo, este tipo en SQL Server solo admite la generación automática de claves primarias y no permite la inserción de una fila con una clave primaria definida por el usuario. A continuación, se notifica un error y no pude solucionarlo. Los proyectos [spring-jdbc-01 y 02] utilizan la tabla [PRODUCTS] sin generación automática de claves primarias. El proyecto [spring-jdbc-03] utiliza la tabla [PRODUCTS2] con generación automática de claves primarias.

    Ahora, ejecuta las configuraciones:

    • [spring-jdbc-generic-01.IntroJdbc01];
    • [spring-jdbc-generic-01.IntroJdbc02];
    • [spring-jdbc-generic-03.JUnitTestDao1];
    • [spring-jdbc-generic-03.JUnitTestDao2];

    Todos deberían pasar.

    Ahora generemos la base de datos [dbproduitscategories]. Repita el procedimiento utilizado para crear [dbproduits] para [dbproduitscategories]. El script SQL que hay que cargar se encuentra en [<examples>\spring-database-config\sqlserver\databases\ dbproduitscategories.sql] ;

      

    Ahora, ejecuta las configuraciones:

    • [spring-jdbc-generic-04.JUnitTestDao];
    • [spring-jpa-generic-JUnitTestDao-openjpa];

    Ambas deberían pasar.

    • líneas 18-22: el controlador JDBC de SQL Server;

    El segundo cambio se encuentra en la clase [ConfigJdbc], que define las credenciales de la base de datos:

    
    // paramètres de connexion
    public final static String DRIVER_CLASSNAME = "com.microsoft.sqlserver.jdbc.SQLServerDriver";
    public final static String URL_DBPRODUITS = "jdbc:sqlserver://localhost\\SQLEXPRESS:1433;databaseName=dbproduits";
    public final static String USER_DBPRODUITS = "sa";
    public final static String PASSWD_DBPRODUITS = "msde";
    public final static String URL_DBPRODUITSCATEGORIES = "jdbc:sqlserver://localhost\\SQLEXPRESS:1433;databaseName=dbproduitscategories";
    public final static String USER_DBPRODUITSCATEGORIES = "sa";
public final static String PASSWD_DBPRODUITSCATEGORIES = "msde";

    La tercera modificación que se puede realizar es la del número máximo de parámetros que puede admitir un [PreparedStatement]:

    
    // max number of parameters of a [PreparedStatement]
    public final static int MAX_PREPAREDSTATEMENT_PARAMETERS = 2000;

    La prueba [JUnitTestPushTheLimits] genera sentencias SQL para 5.000 productos, lo que dará lugar a la creación de objetos [PreparedStatement] con 5.000 parámetros. MySQL admitió este valor. SQL Server devolvió un error indicando que este límite era de 2.100.

    El cuarto cambio se encuentra en la tabla utilizada por el proyecto [spring-jdbc-03]. Ya no es [PRODUCTS], sino [PRODUCTS2]:

    
    // ordres SQL [jdbc-03]

    public final static String V2_DELETE_ALLPRODUITS = "DELETE FROM PRODUITS2";
    public final static String V2_DELETE_PRODUITS = "DELETE FROM PRODUITS2 WHERE ID=?";
    public final static String V2_SELECT_ALLPRODUITS = "SELECT ID, NOM, CATEGORIE, PRIX, DESCRIPTION FROM PRODUITS2";
    public final static String V2_SELECT_PRODUIT_BYID = "SELECT NOM, CATEGORIE, PRIX, DESCRIPTION FROM PRODUITS2 WHERE ID=?";
    public final static String V2_SELECT_PRODUIT_BYNAME = "SELECT ID, CATEGORIE, PRIX, DESCRIPTION FROM PRODUITS2 WHERE NOM=?";
public final static String V2_UPDATE_PRODUITS = "UPDATE PRODUITS2 SET NOM=?, PRIX=?, CATEGORIE=?, DESCRIPTION=? WHERE ID=?";

    13.3. Configuración de la capa JPA de OpenJPA

     

    El proyecto [sqlserver-config-jpa-openjpa] configura la capa [JPA] de la arquitectura de pruebas:

    El proyecto es análogo al proyecto de configuración [mysql-config-jpa-openjpa] para la capa JPA de OpenJpa del SGBD MySQL (véase la sección 8.3). De hecho, ambos SGBD utilizan la anotación [@GeneratedValue(strategy = GenerationType.IDENTITY)] para generar claves primarias. Hay que realizar dos cambios. Se encuentran en la definición del bean [jpaVendorAdapter] en la clase [ConfigJpa]:

    
    // the provider JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        OpenJpaVendorAdapter openJpaVendorAdapter = new OpenJpaVendorAdapter();
        openJpaVendorAdapter.setShowSql(false);
        openJpaVendorAdapter.setDatabase(Database.SQL_SERVER);
        openJpaVendorAdapter.setGenerateDdl(true);
        return openJpaVendorAdapter;
}
    • Línea 6: Le indicamos a la implementación de JPA que va a trabajar con una base de datos SQL Server. La implementación de JPA adoptará entonces tanto los tipos de datos propios como el SQL propio de este SGBD.

    El segundo cambio se refiere a las entidades JPA asociadas a las tablas [PRODUCTS] y [PRODUCTS2]:

      

    La entidad [Product] está asociada a la tabla [PRODUCTS] sin generación automática de claves primarias (sin la anotación [@GeneratedValue]):

    
@Entity(name = "Produit1")
@Table(name = ConfigJdbc.TAB_PRODUITS)
public class Produit {
 
// fields
@Id
@Column(name = ConfigJdbc.TAB_PRODUITS_ID)
private Long id;

    La entidad [Product2] está asociada a la tabla [PRODUCTS2] con generación automática de claves primarias:

    
@Entity(name = "Produit2")
@Table(name = ConfigJdbc.TAB_PRODUITS2)
public class Produit2 {
 
// fields
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
@Column(name = ConfigJdbc.TAB_PRODUITS_ID)
private Long id;

    Además, el proyecto que genera la base de datos [dbproduits] debe modificarse para indicar que ahora hay dos entidades JPA en la base de datos:

      

    El archivo [persistence.xml] cambia de la siguiente manera:

    
<?xml version="1.0" encoding="UTF-8"?>
<persistence version="1.0" xmlns="http://java.sun.com/xml/ns/persistence" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:schemaLocation="http://java.sun.com/xml/ns/persistence http://java.sun.com/xml/ns/persistence/persistence_1_0.xsd">
    <persistence-unit name="generic-jpa-entities-dbproduits" transaction-type="RESOURCE_LOCAL">
        <!-- entities JPA -->
        <class>generic.jpa.entities.dbproduits.Produit</class>
        <class>generic.jpa.entities.dbproduits.Produit2</class>
        <exclude-unlisted-classes>true</exclude-unlisted-classes>
    </persistence-unit>
</persistence>

    El proyecto [generic-create-dbproduits] es común a todos los SGBD. La capa JPA de los examinados anteriormente no contaba con la entidad [Product2]. Cabría preguntarse, entonces, si hacer referencia a una entidad JPA inexistente provocaría el fallo del proyecto en estos SGBD. Las pruebas demuestran que no es así.

    Una vez realizados estos cambios, la ejecución de la configuración [spring-jpa-generic-JUnitTestDao-openjpa] debería completarse con éxito.
